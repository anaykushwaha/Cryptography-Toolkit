````markdown
# GUI Package Documentation

## Overview

The `gui` package contains the complete graphical user interface
for the Cryptography Toolkit.

It provides the visual layer through which users can interact
with the toolkit without directly using the command-line
interface or Python API.

The package is responsible for:

- Application startup and shutdown
- Main application control
- Window management
- GUI widgets
- Dialogs
- Themes and styling
- Navigation between application views
- Displaying encryption and decryption results
- Displaying cryptanalysis results
- Application settings
- History visualization
- Help and about information
- GUI-level error handling
- Integration with the core toolkit


---

## Package Structure

```text
gui/
│
├── __init__.py
├── app.py
├── dialogs.py
├── themes.py
├── widgets.py
└── windows.py
````

---

# 1. `__init__.py`

## Purpose

The `__init__.py` file defines the `gui` directory as a Python
package and provides a centralized public interface for the
GUI modules.

It imports the public functionality exposed by:

* `app`
* `windows`
* `widgets`
* `themes`
* `dialogs`

It also contains basic package metadata.

## Responsibilities

* Initialize the GUI package
* Expose GUI modules
* Provide package metadata
* Define the package-level `__all__`
* Simplify imports from the `gui` package

---

# 2. `app.py`

## Purpose

`app.py` contains the primary application controller.

It is responsible for initializing the graphical environment,
connecting the GUI components together, managing application
state, handling application events, and integrating the GUI
with the rest of the Cryptography Toolkit.

## Main Components

### `ApplicationConfig`

Stores application-level configuration.

Examples include:

* Application name
* Version
* Window dimensions
* Minimum window dimensions
* Theme
* Resizing behavior
* History support
* Logging support
* File-operation support
* Application directories

### `ApplicationState`

Stores runtime application state.

Tracks:

* Current application state
* Current view
* Status message
* Initialization state
* Running state
* Closing state
* Encryption count
* Decryption count
* Analysis count
* Error count

### `ApplicationEvent`

Represents events generated by the application.

Events can be:

* Emitted
* Observed by callbacks
* Cancelled when appropriate

### `CryptographyApplication`

The main GUI application controller.

Responsibilities include:

* Creating the Tkinter root
* Initializing the theme manager
* Initializing the window manager
* Creating the main window
* Configuring application-level events
* Starting the GUI
* Managing navigation
* Updating status messages
* Recording operations
* Handling shutdown
* Managing application callbacks

### `ToolkitController`

Provides an integration layer between the GUI and the
cryptography/analysis packages.

It handles:

* Encryption
* Decryption
* Cryptanalysis
* Cipher selection
* Analysis selection
* Error handling
* Operation tracking

### `ApplicationOperations`

Provides high-level operations used by GUI components.

Supports:

* Text encryption
* Text decryption
* Text analysis
* File reading
* File writing
* Result exporting
* Operation state management

### `ApplicationContext`

Provides shared application information to GUI components.

It gives widgets and windows access to:

* Application configuration
* Application state
* Application operations
* Shared contextual data

## Important Functions

```python
create_application()
run_application()
initialize_application()
get_application()
set_application()
reset_application()
start_application()
stop_application()
restart_application()
```

Additional helpers are provided for:

* Navigation
* Encryption
* Decryption
* Analysis
* Error handling
* Event management
* Diagnostics

## Entry Point

`app.py` also provides a module-level `main()` function that
can be used to launch the GUI application.

# GUI Architecture

The GUI package follows a layered structure.

```text
                    ┌───────────────────────┐
                    │      app.py           │
                    │ Application Controller│
                    └───────────┬───────────┘
                                │
             ┌──────────────────┼──────────────────┐
             │                  │                  │
             ▼                  ▼                  ▼
      ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
      │  windows.py │    │ widgets.py  │    │  dialogs.py │
      │   Windows   │    │   Widgets   │    │   Dialogs   │
      └─────────────┘    └─────────────┘    └─────────────┘
             │                  │                  │
             └──────────────────┼──────────────────┘
                                │
                                ▼
                       ┌─────────────────┐
                       │   themes.py     │
                       │ Styling/Themes  │
                       └─────────────────┘
                                │
                                ▼
                  ┌──────────────────────────┐
                  │   Core Toolkit Packages  │
                  │                          │
                  │ cipher / analysis /      │
                  │ fileio / utils           │
                  └──────────────────────────┘
```

The GUI should primarily act as a presentation and interaction
layer.

Core cryptographic and analytical logic should remain inside
their respective packages rather than being duplicated inside
GUI modules.

The application tracks its runtime state using
`ApplicationState`.

```text

   │
   ▼

   │

   │                   │
   │                   ▼
   │                RUNNING
   │

   │
   ▼
```

This prevents invalid application operations and provides a

# Error Handling

GUI errors should be handled without allowing unexpected
exceptions to crash the entire application.

The application provides:

* `ApplicationError`
* `ApplicationConfigurationError`
* `ApplicationStateError`
* `ApplicationInitializationError`
* `handle_application_error()`
* `safe_execute()`

Errors can be:

1. Recorded by the application
2. Displayed to the user
3. Reflected in the application status bar
4. Returned safely from callback operations

The GUI should never silently alter or hide errors produced
by the underlying cryptographic modules.

The GUI does not implement its own complete file-management

Instead, it communicates with the `fileio` package.

```text
GUI
 │
 ▼

 │
 ▼

 ├── history.py
```

This keeps file handling separate from visual presentation.

The theme manager is initialized during application startup

# Design Principles

The GUI package follows several architectural principles.

## Separation of Concerns

The GUI handles presentation and user interaction.

Cryptographic algorithms remain in `cipher/`.

Cryptanalysis remains in `analysis/`.

File operations remain in `fileio/`.

Shared infrastructure remains in `utils/`.

## Reusability

Common GUI behavior should be implemented once and reused
through:

* Base classes
* Reusable widgets
* Dialog helpers
* Theme managers
* Application utilities

## Centralized Application Control

`CryptographyApplication` acts as the primary controller
rather than allowing individual windows to independently
manage the entire application.

## Lazy Integration

Core toolkit modules are imported where necessary rather than
forcing every GUI import to immediately load the entire
application stack.

This improves modularity and testability.
